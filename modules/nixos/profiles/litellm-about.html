LiteLLM: what is served here, and why

The fleet's model gateway. Everything that talks to a language model goes through this proxy, so this page is the one place that says what is reachable and on whose hardware it runs.

One model per box

Two hardware options are under consideration — a ~32 GB GPU and a 128 GB unified-memory machine — so there is exactly one open model for each, and nothing else. qwen3.8-27b fits the smaller box; nemotron-3.5-super-vl needs the larger one. If the big model measures no better than the small one, that is evidence the 128 GB box buys nothing; note its SWE-bench Pro 51.78 roughly equals a 15.88 GB model's 51.2.

The caveat on the larger tier: the model a 128 GB owner would actually run is Qwen3.8-Flash-Next — the overwhelming community choice for that hardware — and no mainstream provider serves it per-token, so it can be bought but not cheaply tested. Nemotron loses to it on NVIDIA's own published numbers (SWE-bench Pro 51.78 against 60.37), so this tier is being measured by its weakest credible representative. Careful with the near-miss, too: qwen3.8-flash is a different, managed model, and several providers resell it while quoting Flash-Next's specifications.

Why this list looks odd on purpose

These are not the best models money can buy. They are, deliberately, models that would fit on hardware we are considering buying — because this gateway is currently running a measurement: a month of real traffic against rentable versions of models we could host ourselves, to find out what owning the hardware would have cost and whether the output would have been good enough.

Renting a model no home box could run would answer neither question. So DeepSeek-V4, GLM-5.3, Kimi K3, MiniMax and Qwen3-Coder-480B are absent even though several of them are better. Claude stays, as the baseline to beat.

Two things to know when reading the results

No provider serves GGUF. Our self-host targets sit at 5.1–6.2 bits per weight; providers offer fp4, fp8 and bf16. fp8 is the closest tier and is pinned in the request body, so quality measured here is a mild upper bound on what self-hosting would give.

This cannot measure prefill latency. A provider's datacentre GPU produces first tokens far faster than the card we would buy, and prefill — not generation — is what dominates long agent loops. Responsiveness here is not responsiveness we would own.

Nothing here is EU-resident. An EU-pinned route for the nightly log review was priced at roughly five times the cheapest path and dropped as not worth it for one month. So for the duration, fleet-log prompts — hostnames, IPs, service topology — go to whichever fp8 provider OpenRouter selects. Retention is constrained by zdr and data_collection: deny; geography is not constrained at all. A decision to keep renting rather than buy should reopen this, because at that point it stops being temporary.

Where the numbers live

LiteLLM exports per-request cost and token counters, scraped by the monitoring server on the same host. litellm_spend_metric is real money by model; the cached-token counters say whether prompt caching is working, which is the difference between a cheap month and an expensive one.
